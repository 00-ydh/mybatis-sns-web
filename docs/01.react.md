# 1. 웹 개발과 React

## 1.1 SPA와 React 도입 배경
- 전통적인 웹 애플리케이션: 브라우저가 화면을 이동하거나 데이터를 갱신할 때마다 서버에 매번 새로운 HTML 페이지 전체를 요청. 페이지 전체가 깜빡거리며 새로고침되므로 사용자 경험(UX) 저하 발생.
- 단일 페이지 애플리케이션(SPA, Single Page Application): 최초 1회 전체 HTML 페이지를 로드한 뒤, 이후 화면 전환이나 데이터 갱신 시 서버로부터 필요한 JSON 데이터만 비동기로 수신하여 화면의 일부분만 동적으로 교체.
- React 라이브러리: Meta(구 Facebook)에서 개발한 사용자 인터페이스 구축용 오픈소스 JavaScript 라이브러리. 복잡한 DOM 조작과 상태 추적의 어려움을 해결하기 위해 컴포넌트 기반 아키텍처와 가상 DOM 메커니즘 도입.

## 1.2 React 핵심 특성
### 1.2.1 컴포넌트 기반 개발
- 화면을 독립적이고 재사용 가능한 단위인 컴포넌트로 분할하여 구성.
- 각 컴포넌트는 자체 로직과 화면 마크업을 보유하며, 컴포넌트의 유기적 결합을 통해 복잡한 웹 애플리케이션을 체계적으로 조립.

### 1.2.2 단방향 데이터 흐름
- 데이터는 항상 부모 컴포넌트에서 자식 컴포넌트 방향으로만 전달.
- 상태 변경 흐름이 단방향(State -> UI -> Event -> State 변경 -> UI 리렌더링)으로 형성되어 예측 가능성 증대 및 버그 추적 용이.

### 1.2.3 가상 DOM (Virtual DOM)
- 실제 브라우저 DOM과 동일한 구조를 갖는 가벼운 JavaScript 객체 메모리 트리.
- 상태 변화 발생 시 가상 DOM을 먼저 갱신하고, 이전 가상 DOM과의 차이점(Diffing)을 비교하여 실제로 바뀐 부분만 브라우저 DOM에 선택적으로 반영(Reconciliation).

## 2.1 프론트엔드 빌드 도구

## 2.3 경로 별칭(alias) 설정
### 2.3.1 vite.config.ts 수정
- 소스 코드 import 시 복잡한 상대 경로 대신 @ 기호를 사용하여 src 디렉터리를 가리키도록 alias 설정 추가:
  ```ts
  import react from '@vitejs/plugin-react'
  import { defineConfig } from 'vite'
  import { fileURLToPath, URL } from 'node:url'

  export default defineConfig({
    plugins: [react()],
    resolve: {
      alias: {
        '@': fileURLToPath(new URL('./src', import.meta.url))
      }
    },
  })
  ```

### 2.3.2 tsconfig.app.json 수정
- 에디터와 TypeScript 컴파일러가 경로 별칭을 정상 인식하도록 paths 설정 추가:
  ```json
  {
    "compilerOptions": {
      "paths": {
        "@/*": ["./src/*"]
      },
      // 기존 설정은 그대로 유지
      // ...
    }
  }
  ```

## 2.4 첫 번째 React 컴포넌트 작성
- 💻 실습 (카운터 페이지): [src/pages/01_Counter.tsx](../src/pages/01_Counter.tsx)
- 개발 환경 구동 후, 화면 갱신 메커니즘을 직접 확인할 수 있는 카운터 컴포넌트를 독립 페이지 파일로 작성하고 App.tsx에서 직접 렌더링 검증.

### 2.4.1 src/pages/01_Counter.tsx 코드 작성
```tsx
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div style={{ padding: '24px', fontFamily: 'sans-serif' }}>
      <h2>01 Counter - React 시작하기</h2>
      <hr />
      <p>현재 카운트: {count}</p>
      <button onClick={() => setCount(count - 1)}>
        1 감소
      </button>
      <button onClick={() => setCount(0)} style={{ marginLeft: '8px' }}>
        초기화
      </button>
      <button onClick={() => setCount(count + 1)} style={{ marginLeft: '8px' }}>
        1 증가
      </button>
    </div>
  );
}

export default Counter;
```

## 2.5 화면 전환을 위한 React Router 도입

### 2.5.1 React Router 설치 명령어
- 프로젝트 루트 디렉터리 터미널에서 다음 명령 실행:
  ```bash
  npm install react-router
  ```

### 2.5.2 React Router 핵심 컴포넌트
- 최신 표준 임포트 구문
  ```tsx
  import { BrowserRouter, Routes, Route, Link, NavLink } from 'react-router';
  ```
- 핵심 컴포넌트 역할
  - BrowserRouter: HTML5 History API를 활용하여 UI와 브라우저 URL 간 동기화를 총괄하는 최상위 라우팅 래퍼.
  - Routes: 현재 브라우저 URL 경로와 일치하는 자식 Route 컴포넌트 하나를 찾아 화면에 마운트하는 컨테이너.
  - Route: 특정 path(경로)와 해당 경로에 접근했을 때 렌더링할 element(컴포넌트)를 1:1로 매핑.
  - NavLink: 현재 활성화된(isActive) 경로와 일치할 때 활성 스타일이나 클래스를 동적으로 부여할 수 있는 네비게이션 전용 컴포넌트.

    textDecoration: 'none',
    fontWeight: isActive ? ('bold' as const) : ('normal' as const),

    color: isActive ? '#fff' : '#333',
  });

  return (
    <BrowserRouter>
      <div style={{ fontFamily: 'sans-serif' }}>
        <nav style={{ padding: '16px 24px', borderBottom: '1px solid #ddd', backgroundColor: '#fafafa', display: 'flex', flexWrap: 'wrap', gap: '8px' }}>

# 3. JSX 문법 및 작성 규칙

## 3.1 JSX 정의 및 변환 원리
- JSX(JavaScript XML): JavaScript 파일 내에서 HTML과 유사한 마크업 문법을 작성할 수 있도록 지원하는 구문 확장 문법.
- 브라우저는 JSX를 직접 해석할 수 없으므로, 번들러(Vite/ESBuild)가 컴파일 시점에 React.createElement() 함수 호출 코드로 변환 처리.
  ```jsx
  // JSX 작성 코드
  const element = <h1 className="title">Hello React</h1>;

  // 번들러 변환 결과
  const element = React.createElement('h1', { className: 'title' }, 'Hello React');
  ```

## 3.2 JSX 핵심 문법 규칙
### 3.2.1 단일 루트 요소 반환
- 컴포넌트가 반환하는 JSX는 반드시 단 하나의 루트 태그로 감싸져 있어야 함.
- 루트 태그가 두개 이상이 될 경우에는 빈 태그 형태의 React Fragment(<> ... </>)로 전체를 감싸서 하나의 태그로 구성.

### 3.2.2 모든 태그 닫기
- HTML에서는 생략 가능했던 input, img, br 등의 태그도 JSX에서는 반드시 닫는 태그 명시 필요 (예: `<img src="logo.png" alt="logo" />`, `<br />`).

### 3.2.3 카멜 표기법(camelCase) 속성명 준수
- DOM API 속성 명명 규칙을 따르므로 HTML 속성명을 카멜 표기법으로 작성.
- class 대신 className을 사용하며, label의 for 속성 대신 htmlFor 적용 (예: onClick, strokeWidth, tabIndex).

### 3.2.4 중괄호 { }를 통한 표현식 바인딩
- 마크업 내부에서 JavaScript 변수, 연산식, 함수 호출 결과를 출력할 때는 중괄호 { } 사용.
- if문이나 for문 같은 제어문은 직접 삽입할 수 없으며, 삼항 연산자나 논리곱(&&) 연산자, map 메서드 활용.

### 3.2.5 객체 형태의 인라인 style 속성
- 인라인 스타일은 문자열이 아닌 JavaScript 객체 형태로 전달.
- CSS 속성명 역시 카멜 표기법으로 지정 (예: style={{ backgroundColor: '#f0f0f0', fontSize: '16px' }}).

## 4.1 컴포넌트 기반 아키텍처

# 5. 이벤트 처리와 상태 관리(State)

## 5.1 React 이벤트 처리 메커니즘
- 브라우저 기본 DOM 이벤트가 아닌 React의 합성 이벤트(SyntheticEvent) 객체를 통해 크로스 브라우징을 지원하는 일관된 이벤트 핸들링 제공.
- 인라인 속성에 함수 실행문(onClick={handleClick()})이 아닌 함수 참조값(onClick={handleClick}) 또는 화살표 함수 콜백 전달.
- 기본 브라우저 동작(폼 제출 시 페이지 새로고침 등)을 중단하기 위해 이벤트 객체의 e.preventDefault() 호출.

## 5.2 useState 훅을 활용한 상태 관리
- 상태(State): 컴포넌트 내부에서 변경될 수 있고, 변경 시 화면 리렌더링을 유발하는 동적 데이터.
- React.useState API:
  ```tsx
  const [state, setState] = useState<T>(initialValue);
  ```
- 상태 갱신 규칙:
  - 상태 변수를 직접 수정(state = newValue)하면 리렌더링이 발생하지 않으므로 반드시 setState 함수 호출.
  - 배열이나 객체 상태를 갱신할 때는 기존 객체를 직접 변형하지 않고, 전개 연산자([...prev, newElement])를 통해 새로운 참조값을 생성하여 setter에 전달하는 불변성 유지 필수.

# 6. 백엔드 API 연동

## 6.1 useEffect 훅 동작 원리
- 컴포넌트의 생명주기(마운트, 업데이트, 언마운트)와 외부 시스템(네트워크 통신, 타이머 등)을 동기화하기 위한 리액트 훅.
- 의존성 배열(Dependency Array):
  - 빈 배열([]): 컴포넌트가 화면에 처음 나타나는 마운트 시점에 단 1회만 실행 (주로 초기 데이터 조회에 활용).
  - 특정 변수 포함([id]): 지정한 변수의 값이 변경될 때마다 이펙트 콜백 재실행.

## 6.2 fetch API를 활용한 비동기 통신
- 브라우저 내장 fetch() 함수를 사용하여 백엔드 REST API 서버와 JSON 데이터 송수신.
- 비동기 처리 흐름: 데이터 요청 -> 로딩 상태 표시 -> 응답 수신(JSON 파싱) -> State 저장 -> 화면 리렌더링.
- 에러 처리: 네트워크 통신 오류에 대비하여 try-catch 블록과 에러 상태를 함께 관리.

```tsx
import { useState, useEffect } from 'react';
import PostCard from './PostCard';

interface Post {
  id: number;
  memberId: number;
  content: string;
  likeCount: number;
}

function ApiSns() {
  const [posts, setPosts] = useState<Post[]>([]);
  const [loading, setLoading] = useState<boolean>(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    // 마운트 시 1회 실행되는 비동기 데이터 fetch
    fetch('/api/v1/posts')
      .then((response) => {
        if (!response.ok) {
          throw new Error(`HTTP 통신 에러: ${response.status}`);
        }
        return response.json();
      })
      .then((data: Post[]) => {
        setPosts(data);
        setLoading(false);
      })
      .catch((err) => {
        setError(err.message);
        setLoading(false);
      });
  }, []);

  return (
    <div style={{ padding: '20px', maxWidth: '500px', margin: '0 auto', fontFamily: 'sans-serif' }}>
      <header style={{ borderBottom: '2px solid #222', paddingBottom: '10px', marginBottom: '20px' }}>
        <h2>05 API 연동 - MyBatis SNS</h2>
      </header>

      {loading && <p>게시글 목록을 불러오는 중...</p>}
      {error && <p style={{ color: 'red' }}>에러 발생: {error}</p>}

      {!loading && !error && posts.length === 0 && (
        <p>등록된 게시글이 없습니다. (백엔드 서버 구동 여부 확인 필요)</p>
      )}

      {!loading && !error && posts.map((post) => (
        <PostCard
          key={post.id}
          memberId={post.memberId}
          content={post.content}
          likeCount={post.likeCount}
        />
      ))}
    </div>
  );
}

export default ApiSns;
```
